**v0.8.2: optional speed experiments, all off by default.** `start-stage-a.ps1` without switches runs like v0.8.1, except that the default `balanced` plan is now the split that ran (`ngl=29`, `ts=7,7,2,7,6`) and the API port is 8081. Engine:
- `LLAMA_MOE_PREFETCH=1`: `src/llama-moe-prefetch.cpp` adds a one-thread CPU custom op after the router in `build_moe_ffn` for layers whose expert tensors are host weights; it calls `PrefetchVirtualMemory` (Windows) or `posix_madvise(WILLNEED)` on the selected experts' slabs, or on whole tensors when half or more of the experts are selected.
- `GGML_SCHED_PROFILE=1`: `ggml_backend_sched` sums per-backend run time (synchronized) and fetch time (copies of its outputs, which includes waiting for remote compute), split into graphs of up to 8 tokens and larger ones, and logs `sched_profile` lines every 30 s.
- Workers: `GGML_RPC_SERVER_PROFILE=1` adds busy ms/graph to `[stats]`; `GGML_RPC_SERVER_LOCAL_COPY=1` makes `rpc_server::copy_tensor` stage through host memory when the backends cannot copy directly (CPU to CUDA), protocol unchanged.
- `llama-fit-params` accepts `--spec-type`, so Gate 2 projects the MTP block like the server's own check.

**2026-10-25 hardware run (v0.8.2, `-Prefetch -Timing`, balanced): 3.65 tok/s prompt, 1.77 tok/s generation.** Claude's [follow-up research](docs/SPEED_RESEARCH-2026-10-25.md) (no code changed) finds the fused DeepSeek V4 HC post disabled for the whole model by a false-positive device check at the CPU-to-4090 boundary (layer 17). The unfused fallback roughly doubles the graph (14758 nodes) and makes every device boundary copy 18 tensors instead of 2: 384 KiB per hop and about 90 synchronous RPC round trips (about 54 ms) per token. GPU layers cost 9-21 ms each, a per-node cost of unknown cause (launch overhead or clocks). The 2026-10-24 research's memory figures had a MiB/GiB slip (A maps 40.2 GiB, not 41.2) and are corrected. **v0.8.3 (current source): the 2026-10-25 fixes, all opt-in** ([test plan](docs/TEST-PLAN-v0.8.3.md)):
- `-FusedHc` on A sets `LLAMA_FUSED_HC_FIX=1`. In `llama_context::resolve_fused_ops`, a fused node on another device is accepted when both devices support the op, which keeps the fused HC post on and makes each device boundary copy 2 tensors instead of 18.
- `-Timing` now also reports the slowest graph per 30-s window with run + fetch per device, and workers report the slowest graph per `[stats]` line.
- The v0.8.2 shutdown timing report was a use-after-free: it read device names from backends llama.cpp had already freed. Names are now copied when the scheduler is created.
- `-NoCudaGraphs` on A, B and C sets `GGML_CUDA_DISABLE_GRAPHS`.
- Plan `relief`: `tight` plus one layer in C's RAM; Gate 2 decides.
- Plan `gpu-attn` (experimental): `ngl 47`, `ts 25,7,2,7,6`, `--n-cpu-moe 19`, so the 4090 runs the non-expert parts of layers 0-18 and the CPU only computes their routed experts. With it, `-MoeCacheMib N` passes upstream `--moe-cache-mib`, which Gate 2 counts under context.
