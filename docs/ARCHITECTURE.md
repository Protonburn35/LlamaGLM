# Three-stage GLM architecture

Status: partial implementation. Ownership/planning, owned-layer evaluation and authenticated transport components exist. A constrained three-process CPU fixture runs actual A/B/C layer work; production network services do not.

The initial plan is A [0,22), B [22,27), C [27,45). A owns token embeddings and future matching GLM5V preprocessing; C owns final mHC collapse, normalization, output head and optional one-block NextN. The planner rejects empty stages, gaps, overlap, missing coverage and unknown global tensors. NextN block 45 is distinct from target layers 0 through 44. Split counts are configurable and must cover the complete target model.

The existing graph in `src/models/glm5-next.cpp` initializes `inpL` as `[4096,4,rows]`, applies attention and FFN mHC transforms inside each layer, and collapses the four streams only after layer 44. The boundary is after `l_out`, before the next layer's `build_hc_pre`. A contiguous FP32 boundary has 65,536 bytes/token, or 128 MiB for 2,048 rows. A protocol must fragment this into bounded frames. Token positions and pool metadata remain lossless integers. Do not transfer the collapsed `[4096,rows]` head representation at an intermediate boundary.

`build_kda_layer` owns recurrence and Q/K/V short-convolution history per recurrent layer. `build_dsa_layer` owns latent MLA and indexer state per DSA layer. The current indexer stores key, gate and pooled key in each cache row. Every audited trunk DSA layer is a full indexer, so there is no cross-stage indexer-selection reuse in the published schedule. Absolute positions, incomplete four-token pools and recurrent rollback snapshots must remain coherent across chunk boundaries.

The evaluator now executes the validated range and filters all three state components by the same ownership predicate as weight loading. A initializes the four streams from token embeddings. B/C consume contiguous FP32 `[hidden*4,rows]` input, reshaped without reducing precision or collapsing streams. A/B return all boundary rows through the embedding output API, regardless of requested logit flags; only C runs the final collapse, normalization and head. Public batch/result widths reflect these boundary dimensions. Headless graphs omit unused output-ID inputs; pure-KDA or pure-DSA stages omit the other memory inputs. The ordinary monolithic graph remains the comparison oracle.

The experimental C interface in `include/llama-stage.h` now loads only the selected rank's trunk weights, embeddings on A and head on C. It copies a versioned complete three-range plan into each model and excludes unowned file weights before allocating buffers or reading payloads. The default monolithic API remains unchanged. Partial models explicitly refuse ordinary context creation and complete-model export. Stage file loading currently requires buffered NONE and lazy OFF, and rejects MTP; it does not assert residency or implement SSD streaming. The source shard set is still required for metadata; stage-only deployment packs remain distribution work. `llama_model_size`/parameter counts on these stage objects describe the owned payload/elements, excluding allocator overhead.

`llama_init_stage_from_model` is a narrow append-only baseline: one sequence (ID 0), consecutive absolute positions within capacity, causal decoding, FP16 MLA/index cache and source FP32 KDA state. Its defaults select the full model context, bounded at 1,048,576. B/C reject token input. MTP, rollback, backend samplers, pooling, noncausal encode and cross-layer shared index selections are refused. Invalid input/settings are rejected before memory preparation. Once memory preparation/computation fails, that context permanently refuses further decoding, even after a memory clear; recreate it against the retained model. A distributed controller must reset/replay every owner together. This is not a distributed transaction implementation.

Persistent native Windows processes will form A -> B -> C, with a separate bounded authenticated control path to avoid cancellation starvation. C samples; A emits only globally committed output. One active request is sufficient. Startup must require all three matching, capable stages. Future desktop weight providers may stream local SSD experts; B's inference provider must have no SSD fallback and must refuse admission unless all required weights/state have a proven residency policy.

The new CPU pipeline fixture demonstrates this compute chain with three separate processes and a six-layer model. It compares both four-stream boundaries and all C logits against a separate monolithic oracle, verifies exact aggregate weight ownership and refuses direct A-to-C startup without B. The fixture is loopback-only with a per-run temporary secret, fixed small geometry and single-frame chunks; it is not the production worker/coordinator or a residency proof. Real model identity, resource admission, control/session commits and serving still need integration.

Speculation remains off until full-target A/B/C verification and rollback are tested. The existing monolithic MTP implementation is a source reference, not evidence of distributed MTP. Vision, prefix reuse, cancellation and three-stage snapshots likewise require new integration and validation.

`llama_model_validate_stage_schema` accepts complete merged GGUF descriptors and returns only a versioned inventory report. A guarded internal descriptor mode uses the same architecture tensor creation and count checks as normal loading; the virtual provider path cannot synthesize missing tensors. It forces CPU, no allocation, no mmap/lazy provider and includes declared NextN for schema validation. All model handles remain local and are destroyed before return; no weight payload or inference state is allocated. Metadata limits guard native geometry assertions. `llama-glm-plan --validate-schema` exposes this check for the exact four-header inventory. Canonical identities and measured admission are separate gates.
