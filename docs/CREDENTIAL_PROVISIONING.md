# Private locked credentials

`locked_secret` loads an explicitly configured 32-byte nonzero binary key from a local regular file. It reserves dedicated native pages under the caller's page budget, verifies private access on the opened handle, reads directly into those pages, checks access again and closes the source before construction returns. Its runtime type contains no file reader, reload callback or default key. Native lock/cap failure refuses without pageable fallback. It never prints key bytes or a key fingerprint.

On Windows the existing source reader requires a resolved fixed local volume and denies concurrent write/delete handles. Private access additionally requires owner/current-process-user, LocalSystem or built-in Administrators ownership. Every effective allow ACE must name one of those principals; inherit-only entries and deny entries cannot grant access. Null/invalid DACLs, unsupported allow entries and unrelated principals refuse. Security information is queried from the same native handle. Ordinary model files do not use this optional credential policy.

On POSIX the file must have current-user/root ownership and no group/other permission bits. File identity/time checks run before access validation and around the positional read. A private-policy refusal permanently poisons that source instance. This is a file access policy, not encryption at rest or protection from the trusted user/System/administrators.

`value()` exposes a borrowed const key while the owner remains valid. Multiple readers may use it; stop/join them before invalidation or destruction. Explicit invalidation wipes the bytes and refuses later access while preserving the native page charge until destruction. Failed loads and final destruction wipe before unlock/free. Invalidation of the root does not revoke independently derived active connection keys; the coordinator must stop/discard their owners too.

The deployment command `--check-key deployment.json` performs this explicit credential check. It reports private access, native page bytes and zero open credential sources, with no model/tensor/network work. The key remains locked through reporting and is wiped on exit. Ordinary `--check`, header inspection and reference audit retain their previous credential-unread behavior. All modes keep admission `NOT_VALIDATED`; no key creation, silent reload, peer connection or READY occurs.

Use a cryptographically generated raw 32-byte key, not a hex/text representation. Create private local storage before writing credential bytes, and provision the same key to the intended peers through an approved local process. The tool reads a configured file; it does not generate or change production permissions. The example contains only a path. Test helpers protect fresh temporary directories before creating public deterministic unit fixtures or random per-run protocol keys; they never operate on production files.

All actual pipeline workers now load their root through this class. The x64 fixture charges one 4,096-byte native page per process, verifies private access, closes its source before model loading and preserves the cached root across fresh authentication and retained-context replay. It wipes only after the root is no longer needed. Existing applied/commit/retry/result byte ledgers and every independent graph/generation oracle remain exact. No credential reader survives into inference.

The new six-suite component test rejects public/zero/short/cap-invalid sources, checks failed-load cleanup, deletes a private source while keys remain active, uses eight concurrent HMAC readers, verifies quiescent wipe and independent owners, and requires final native charges to return to baseline. ASan/UBSan and TSan pass with the existing real-kernel mlock wrapper. The expanded sixteen-CTest/seven-GLM gate passes, including explicit CLI private/public credential checks and every actual model/retry/recovery profile. Native Windows ACL/working-set qualification is pending.

This protects the configured root payload. Owner metadata, protocol key copies, crypto provider allocations, control/network headers, threadpools, CUDA staging and GPU/WDDM resources still need complete protection/accounting. Model, reply, input and root budgets remain separate fixture caps, not aggregate production admission. Full B residency/READY stays false; real mixed-quant/GPU/physical three-PC/1M execution remains NOT_RUN.
