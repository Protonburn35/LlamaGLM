# Caller-owned activation input

The locked-B CPU fixture now reserves one 131,072-byte native page buffer before peer work. That covers its maximum 64 rows of 128 hidden values/four FP32 streams. All initial inputs, healthy retries and new-epoch replay receive into that same per-context buffer. Native locks are checked after each complete receive and before final evidence. The fixture uses a separate 256 KiB page cap; complete process/model/reply/network admission still requires an aggregate production budget.

`read_frame_into` validates the fixed header and caller capacity before reading a body, reads directly into exclusive caller-owned storage, authenticates the entire frame and only then returns a borrowed view. It allocates no payload vector. Failure clears the accepted body region and permanently interrupts the connection. Header/capacity refusal reads no body and leaves unaccepted caller storage unchanged. The next read can reuse the same buffer; consumers must discard prior borrowed views first.

`receive_boundary_into` reserves no payload storage itself. The caller supplies an admitted float buffer. Each fragment reads directly into its final slice, authenticates, checks complete local coordinates/order and performs any required endian conversion in place. Only the complete chunk returns to the model. Once local capacity is accepted, any failure zeros the complete active chunk and interrupts the stream. A caller must hold exclusive ownership until return and through synchronous consumption; this API cannot revoke a pointer used by another thread.

The existing vector-based receive API remains available for callers without a protected buffer. B's locked fixture uses only the caller-owned path. Its `common_batch` embeddings are non-owning views of the locked input; metadata/control allocations remain outside this protection. Failed epoch scope destruction releases the network pages with the old context, and retained-model recovery creates a fresh protected input buffer.

`sender::encode_header` creates the authenticated fixed header without copying the payload. `write_frame` writes that header followed by the immutable original body against one absolute deadline. One writer owns the connection; the caller must keep bytes unchanged until the write completes. Any partial write requires connection disposal. The original complete-packet encoder retains its allocation-before-sequence-advance behavior for callers that need a copied packet. Independent tests require byte-identical headers and unchanged sequence after refusal. Socket byte ledgers remain identical; syscall counts can differ.

Fourteen boundary suites cover both vector/caller-owned 128 MiB transfers, nontrivial tails/IEEE bits, guard floats, rejected capacities, zeroing after truncation/bad MAC, pre-body frame refusal and existing completion/deadline/coordinate checks. Thirteen wire suites include the separate-header path. Nine native socket suites pass ASan/UBSan and TSan; the fourteen boundary suites also pass ASan/UBSan. An initial build found a missing cstring include; successful reruns follow its correction. The full fourteen-CTest/seven-GLM gate passes, including all real process model/retry/greedy/seeded-feedback/recovery profiles.

B reports seven completed receives/268,288 input bytes without transaction retry; eight/270,336 for the 131-row transactional profile; eighteen/102,400 for each 33-row feedback profile. Protected capacity is fixed at 131,072 bytes in all cases. The model source remains deleted, and its native read counts do not increase.

This covers the activation receive/reassembly payload and removes outgoing packet payload copies. Control message bodies, crypto provider/part-vector allocations, stack/header data, metadata/threadpool structures, kernel buffers, CUDA staging and actual GPU/WDDM resources remain separate work. The native lock primitive is unchanged and has no pageable fallback. Full B working-set residency/admission stays false; physical target/real mixed-quant/GPU/1M execution remains NOT_RUN.
