# Experimental middle-stage expert preload

`llama_model_load_stage_preloaded_from_file` loads rank 1 with a complete routed expert catalog in native locked host pages. It requires `LLAMA_GLM_RPC=ON`, buffered NONE, lazy OFF and the same owned GLM geometry/device/precision restrictions as desktop banks. It has separate raw payload, page-rounded host, entry and per-context bank caps. The complete catalog must fit before any expert is read or locked; no selected-expert-only preload is accepted.

The native loader still validates every required shape/count and excludes unowned tensors. Routed GGML tensors retain full logical descriptors without ordinary full-weight buffers. A startup-only reader fills their exact quantized slabs into dedicated locked pages, seals/verifies the complete memory catalog, and releases all expert-file readers. The inference reader's type contains only the immutable memory store and startup counters, with no file handle, retained callback, desktop cache or disk fallback. Dense/shared owned weights load through the ordinary buffered path.

The graph uses the same leased backend banks, original-ID scale semantics, complete selected expert set, bounded microbatch and permanent-failure handling as desktop streaming. `llama_stage_context_default_params_for_model` chooses a fitting microbatch without reducing context capacity. Multiple contexts reuse the model's locked host catalog; each has its own bounded backend banks and mutable inference state. No full-model replication or expert network transfer is introduced.

`llama_model_stage_preload_report` reports complete slab count, raw/locked bytes, startup reads and zero retained expert source files. Generic storage counters remain at their startup values during inference. `full_residency_validated` remains zero: ordinary weights, metadata, attention/KDA state, scratch, CUDA staging and physical GPU residency have not been admitted. Host payload locks are not CUDA DMA registration. The current production worker/READY path is still absent; this API alone is insufficient for a laptop deployment.

The additional CPU fixture uses a 2/1/3 split so B's 48 complete expert slabs fit below the cloud test lock quota. It locks 4,718,592 payload bytes, removes B's separate GGUF while the model remains loaded, then executes 131 tokens over seven uneven chunks at microbatch 1 against an independent full-model oracle. Both boundaries and logits are byte-exact locally. It requires unchanged startup I/O/lock totals and no claimed full admission, and refuses malformed policy, wrong rank, incomplete-entry and insufficient raw/page budgets. The GLM group now has six local tests.

Native Windows qualification is pending for this API. The Windows CPU test scopes an explicit increase of its own process working-set limits (at least 16 MiB minimum, 64 MiB maximum) around the fixture, then restores them after locked models are destroyed. This is test quota setup, not a production reserve or proof of whole-process residency. Production allocation does not silently change OS limits or fall back to pageable payloads. GPU runtime, real mixed quant model, physical machines and 1M execution remain NOT_RUN.
