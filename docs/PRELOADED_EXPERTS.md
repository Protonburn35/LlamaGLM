# Experimental middle-stage expert preload

`llama_model_load_stage_preloaded_from_file` loads rank 1 with a complete routed expert catalog in native locked host pages. It requires `LLAMA_GLM_RPC=ON`, buffered NONE, lazy OFF and the same owned GLM geometry/device/precision restrictions as desktop banks. It has separate raw payload, page-rounded host, entry and per-context bank caps. The complete catalog must fit before any expert is read or locked; no selected-expert-only preload is accepted.

The native loader still validates every required shape/count and excludes unowned tensors. Routed GGML tensors retain full logical descriptors without ordinary full-weight buffers. A startup-only reader fills their exact quantized slabs into dedicated locked pages, seals/verifies the complete memory catalog, and releases all expert-file readers. The inference reader's type contains only the immutable memory store and startup counters, with no file handle, retained callback, desktop cache or disk fallback. With v1, dense/shared owned weights load through ordinary buffered allocations. Explicit policy 2 below uses the locked host type.

The graph uses the same leased backend banks, original-ID scale semantics, complete selected expert set, bounded microbatch and permanent-failure handling as desktop streaming. `llama_stage_context_default_params_for_model` chooses a fitting microbatch without reducing context capacity. Multiple contexts reuse the model's locked host catalog; each has its own bounded backend banks and mutable inference state. No full-model replication or expert network transfer is introduced.

`llama_model_stage_preload_report` reports complete slab count, raw/locked bytes, startup reads and zero retained expert source files. Generic storage counters remain at their startup values during inference. `full_residency_validated` remains zero: complete model/process/GPU residency has not been admitted. Policy 2 protects tracked host tensor payloads; backend work buffers, metadata, network/staging and GPU admission remain open. Host payload locks are not CUDA DMA registration. The current production worker/READY path is still absent; this API alone is insufficient for a laptop deployment.

The additional CPU fixture uses a 2/1/3 split so B's 48 complete expert slabs fit below the cloud test lock quota. It locks 4,718,592 payload bytes, removes B's separate GGUF while the model remains loaded, then executes 131 tokens over seven uneven chunks at microbatch 1 against an independent full-model oracle. Both boundaries and logits are byte-exact locally. It requires unchanged startup I/O/lock totals and no claimed full admission, and refuses malformed policy, wrong rank, incomplete-entry and insufficient raw/page budgets. The GLM group now has six local tests.

This API passes native Windows CPU in all build variants at 81f4a71cb, run 39546390989. The Windows CPU test scopes an explicit increase of its own process working-set limits (at least 16 MiB minimum, 64 MiB maximum) around the fixture, then restores them after locked models are destroyed. This is test quota setup, not a production reserve or proof of whole-process residency. Production allocation does not silently change OS limits or fall back to pageable payloads. GPU runtime, real mixed quant model, physical machines and 1M execution remain NOT_RUN.


## Explicit shared host policy 2

Set preload.version to 2, model use_extra_bufts=false and tensor_buft_overrides=null. The existing struct layout and v1 behavior stay unchanged. host_payload_bytes still caps the complete raw expert catalog; host_page_bytes now caps its page-rounded native storage together with ordinary host weights, attention/index/recurrent tensor state, scheduler graph buffers, outputs and CPU expert banks across every context using the model. Each context still has its separate bank cap. A failed allocation refuses without a heap fallback. Device buffers retain their device types; this is not GPU admission or CUDA DMA registration.

The source reserves external expert pages before startup reads/locks and retains the resulting memory-only reader alongside native host-buffer ownership. No loader callback survives startup. llama_model_stage_host_report verifies tracked locks and reports the shared model/context reservations and peak. Inspect between decodes and allocation/free operations. full_residency_validated remains zero: CPU backend work_data, metadata, network activations and GPU staging/WDDM resources still need protection and measured admission. Production READY must not treat this report as complete residency.

Local qualification adds a separate small F32 model with FFN 64/shared 32 and four indexer heads. Hidden 128, latent 512, KDA width 128, streams four, all eight of sixteen experts and context 256 remain. B owns either one KDA or one DSA layer. Both independent 131-token oracles are byte-exact after source deletion, with native weights/state/graph buffer-type checks, unchanged expert I/O, shared caps and context cleanup. The GLM group now requires seven local tests. This policy has not yet passed its exact-source Windows run; prior expert-only and primitive Windows evidence remains valid for their pinned sources.


Policy 2 passes native Windows in all variants at 0cd4a9331 (seven GLM tests, five host suites), run 39555445703. Its next follow-up also configures CPU work_data and explicit-plan scratch through the shared pool before backend use, with failure on missing support. The small KDA/DSA fixture uses one thread to fit actual flash-attention scratch below native test quotas; both independent 131-token oracles remain byte-exact. This scratch follow-up awaits native Windows qualification. Full residency remains false for metadata/control/network/staging and physical GPU resources.
