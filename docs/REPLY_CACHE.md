# Bounded immutable transaction replies

reply_cache retains one applied output and the immediately previous locally committed reply for one rank and immutable session/epoch/generation. Replies contain copied unfragmented payload bytes, the complete applied receipt and its output fingerprint. They never borrow graph output memory or spill to disk. Caller-owned payloads must remain stable during capture, and production fingerprints must use the canonical unfragmented byte representation.

Before allocating payload memory, a mutex-protected reservation checks logical bytes, native page-rounded bytes and entry count. Local configured limits are capped at 512 MiB and 16 entries; each payload is nonempty and at most the existing 128 MiB logical boundary ceiling. Both pending and previous replies compete with all externally retained retired leases. Replacing an internal reply cannot release its charge while another sender still holds a strong lease. Native/heap backing is freed before its reservation is released. Lease destruction and immutable reads may occur concurrently; cache mutation remains single-writer.

Memory policy is explicit. Pageable mode owns an ordinary byte allocation and requires page budget zero. Locked mode reserves native page-rounded capacity and uses the existing dedicated locked_pages primitive, including native residency verification. Native allocation/lock failure has no pageable fallback. These reply-specific budgets are separate from the model's host pool and must be included in future combined worker admission. Metadata, accounting, connection frames and other network/control buffers remain outside this payload guarantee; full working-set residency is false.

The output fingerprint is checked against the actual input and the captured immutable copy. Matching applied/committed retries reuse the exact owner rather than allocating again. New output requires consecutive transaction/chunk/position and no existing pending reply. Local commit validates the entire three-owner certificate, matches the actual cached own receipt, and records the full canonical certificate fingerprint. A later certificate with unchanged A receipt but changed C outcome still conflicts. The previous committed reply remains available while the next step is pending; expired replies refuse without model re-execution.

Only call cache.commit after the actual local owner ledger commits successfully. Retaining or committing a reply does not authorize client publication: the coordinator still needs all three distinct commit acknowledgements. A missing reply or capacity refusal requires backpressure or coordinated reset/replay; it cannot cause another graph call for an applied/committed retry.

Explicit invalidation permanently revokes future payload/receipt access through every outstanding lease. The caller first stops/joins consumers and discards all borrowed byte/metadata views: no API can retract already borrowed pointers or sent bytes. Revoked payloads remain allocated and charged until the final lease disappears. Healthy leases can outlive normal cache destruction. No API reactivates an invalidated cache or silently changes its epoch.

The fourth actual model-process fixture now copies each graph output into this cache before applied acknowledgement. B uses a separate 256 KiB native-page reply budget; A/C use explicitly pageable bounded replies. Local cache commit precedes the commit ACK. Diagnostic files and seven committed retries read the immutable cached bytes after the all-three completion notice. Existing exact 131-token oracles, source-deleted complete B catalog and lost-ACK zero-output invalidation remain.

Six focused suites cover immutable copies/source mutation, applied/committed retry and expiry, retained-lease byte/entry caps, dedicated native page rounding/lifetime/refusal, complete-certificate conflicts and lease revocation, and eight participating concurrent weak-retention readers racing final old-reply release. The reusable local gate now has thirteen CTest targets plus seven GLM tests.

Use `bash scripts/glm-replies-sanitizer.sh address` or `thread` for the standalone Linux checks. Sanitizer runtimes can intercept mlock as successful without locking pages. A local ASan probe measured VmLck remaining zero after intercepted mlock and increasing by 4 KiB after the real kernel call; the ordinary ASan run correctly failed native residency verification. The harness uses the existing real SYS_mlock/SYS_munlock wrapper for both sanitizers and preserves production checks. It does not mock lock success. Exact-source native Windows qualification is pending.

The real-kernel-lock reply harness passes all six suites under both ASan/UBSan and TSan with no report. The final full local thirteen-CTest/seven-GLM gate also passes.
