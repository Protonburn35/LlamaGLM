# Native host expert-payload locks

`memory_experts` accepts a separate optional page-lock budget. A positive budget allocates each payload in dedicated native pages and requires a successful lock; no ordinary-heap fallback exists on that path. Windows uses VirtualAlloc/VirtualLock and verifies every page with QueryWorkingSetEx Valid/Locked bits. Linux CPU qualification uses anonymous mmap/mlock and verifies residency with mincore. The ordinary zero-lock-budget store remains explicitly pageable.

Dedicated allocations prevent unrelated heap payloads from sharing VirtualUnlock/munlock lifetimes. Raw payload bytes and page-rounded locked bytes have independent caps, checked before allocation. The immutable lease owns the allocation and lock until its final release, including after the store is destroyed. Process counters retain locked bytes/buffers through that final release. Constructor errors release any native allocation/lock before returning failure. The implementation does not increase process working-set limits or OS privileges automatically; inadequate lock quota is a clear error.

Preload and complete-catalog sealing occur before concurrent inference lookups. `payloads_locked` becomes true only for a sealed nonempty store using the locked policy; `verify_payload_locks` rechecks native pages. `preload_with` fills the owned locked buffer directly through a startup-only reader, then discards that callback before publishing bytes. Failed reads free the incomplete buffer/lock, and reentrant preload/seal calls refuse. There are no file handles, retained read callbacks or eviction paths in the sealed store. Missing experts fail, including when the original preload file is absent. These locks protect host payload pages, not CUDA DMA registration, GPU allocations, allocator/catalog metadata, attention/KDA state, scratch or complete process residency.

This is a host-payload primitive. No current model API selects it, and B's three-process fixture still uses buffered heap. Production laptop admission must connect the complete owned catalog to this source, prove all other owned weights/state/workspace and actual GPU residency, account for metadata and retained allocations, and reject unavailable capacity. These tests do not admit the real target or prove 1M/hardware execution.

Two native tests add page rounding/quota refusal, exact bytes with the preload file removed, eight concurrent readers, retained leases, no locks for ordinary heap and complete final-release accounting. They use only 8 KiB of native locked payload pages locally. The complete storage target now has twelve suites; ordinary CTest always requires the native lock/residency checks.

The base native allocator/lock tests pass Windows CPU in all build variants at 2413c1aec. The startup-reader extension adds exact native preload reads, proof the reader/file owner expires before inference, and rollback after a partial startup failure. Those additions pass locally and under the real-lock sanitizer harness; their exact-source Windows qualification is pending.

For Linux concurrency instrumentation, run `bash scripts/glm-storage-tsan.sh /tmp/glm-storage-tsan`. TSan's default mlock/munlock interceptors are documented by the installed runtime as no-ops; an initial default run correctly failed the real resident-page check. The standalone harness links a test-only wrapper that invokes the real Linux kernel lock/unlock syscalls. It retains the production allocation, quota, residency and lifetime checks and introduces no production test mode or mock lock success. Do not claim a default intercepted run qualified real locks.
