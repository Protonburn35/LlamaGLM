# Experimental desktop stage streaming

`llama_model_load_stage_streamed_from_file` in `include/llama-stage.h` connects local read-only GGUF shards to the owned GLM loader and MoE graph. It requires `LLAMA_GLM_RPC=ON`, rank 0 or 2, buffered NONE and lazy OFF. Rank 1 cannot use this API. This is an experimental local evaluator, not a production worker or resource admission implementation.

The loader validates the ordinary native shapes/counts while skipping allocation and loading for owned routed gate/up/down expert tensors. Full logical descriptors have null data/buffer pointers. Dense/shared/global owned weights still load normally; unowned layers and NextN remain excluded. File offsets and raw quantized slab geometry come from the native split-GGUF loader. The source opens read-only positional handles and constructs the complete owned expert catalog without reading expert payloads.

Each context allocates three projection banks per owned MoE layer on that layer's actual execution backend. Both logical bytes and the backend allocator's padded size must fit the caller's aggregate context bank cap. A CPU custom graph operation reads selected IDs, obtains complete source slabs through the bounded desktop RAM cache, fills the banks and returns remapped GEMM IDs. Original IDs still drive scale/bias gathers. A compute lease keeps each bank alive until backend completion. Provider exceptions are caught inside the worker callback; failed output IDs are zeroed, the provider becomes permanently invalid and the context refuses successful decode output. The scheduler synchronizes before checking this status.

Use `llama_stage_context_default_params_for_model` to obtain an explicit fitting microbatch. The worst-case selected count must fit the bank: `n_ubatch * n_expert_used_max <= bank_slots`. An eight-slot target bank therefore uses microbatch 1 and still keeps every selected expert. This implementation refuses unsupported capacity; it does not implement multi-wave prefill or drop experts. Context capacity remains the full model default (1,048,576 for the target), independently of microbatch size. CPU banks require `op_offload=false` to prevent scheduler copies from retaining stale host weights. Competing stock MoE caches, LoRA, tensor splitting, multiple execution devices and Hadamard-folded weight transforms are refused.

`llama_model_stage_storage_report` separates logical routed bytes, allocated ordinary model buffers, reserved raw host payload and requested native file I/O. It does not report physical SSD traffic, total process working set, pinned memory or GPU residency. Backend banks are also included in context memory accounting. There is no GPU hot-expert retention policy yet; bank materialization copies selected slabs synchronously even on a RAM-cache hit. Synchronous native I/O has no per-read cancellation/deadline integration.

Qualification uses the independent monolithic six-layer F32 CPU fixture. A/C use the actual streamed loader/provider, B uses the buffered owned loader, and all three execute 131 tokens over uneven chunks at microbatch 1. Startup requires zero expert-source reads and null full-expert allocations; inference requires nonzero bounded reads and matching four-stream boundaries/logits. Negative checks cover policy/bank/microbatch caps, laptop fallback, conflicting copy/cache modes and a permanently failed custom callback with no source reads. B's buffered heap is not a physical residency guarantee. Separate bank operator fixtures cover all eight publisher tensor types; the complete streamed model fixture is F32. Real mixed-quant model, GPU runtime, physical machines and 1M execution remain NOT_RUN.
