Local commands after a CPU CMake build:

```sh
ctest --test-dir build -R '^(test-glm-stage|test-glm-plan|test-glm-storage|test-glm-expert-bank|test-glm-wire|test-glm-identity|test-glm-boundary|test-glm-net|test-glm-pipeline|test-gguf)$' --output-on-failure
build/bin/test-llama-archs --arch glm5-next --backend CPU --seed 53 -v 5
```

Require a nonzero completed-test summary from the architecture runner. A zero exit with muted/no summary is insufficient evidence by itself. Tests are assertions/checks in Release builds too; new checks do not rely on disabled C assertions.

Wire/auth tests require `-DLLAMA_GLM_RPC=ON`. Twelve component suites exercise an RFC 4231 HMAC vector, independent Python-derived key/header/MAC/challenge vectors, every frame/handshake envelope byte and selected payload corruptions, wrong identity/direction/channel/key, replay/skipped frame and handshake rejection, fatal invalidation, forged lengths/counts before payload allocation, control/data separation and a 128 MiB logical boundary processed in bounded 4 MiB fragments. Local backend: OpenSSL 3.5.7; all twelve suites also pass native Windows CNG at 79d638759. These are byte-component tests; the separate bridge tests cover whole-chunk reassembly, and the model fixture covers computation. Distributed transactions remain unimplemented.

Eight additional TCP suites pass on local Linux and native Windows Winsock at 52d499a2e with actual loopback sockets in one process: fresh mutual proof, bit-preserving 4 MiB/64 KiB two-way fragments, cancel acknowledgement on an independent control socket while data is backpressured, deadline/EOF permanent shutdown, wrong secret refusal, malformed lengths rejected without reading a body, explicit interface/port conflict and concurrent read/listener interruption. No model executes in these component tests.

The separate test-glm-pipeline launches three distinct native CPU worker processes. Each loads only its own layers through the stage loader (2/2/2), owns its own recurrent/MLA/index state, and computes actual graph work. A sends all four FP32 streams to B, B computes and forwards to C, and C runs the final head. A separate monolithic generator writes both reference boundaries and all logits before workers start. For 131 tokens over seven uneven chunks, both boundaries and logits are byte-exact under GCC 14.2 and MSVC 19.44 (maximum error 0). The independent tensor-byte total equals the sum of the three reported stage payloads. Direct A-to-C startup without B refuses before any inference output. Windows CPU and both CUDA-linked builds pass at e5a94c203; all model execution remains CPU.

The worker binary is test-only, loopback-only, requires a fresh per-run secret file from the harness, and refuses models without the small six-layer fixture marker/geometry. No worker credential default is embedded or logged. It creates no user service. The generated 80 MiB F32 GGUF and references are temporary synthetic data, not downloaded real weights. Context is 256, not 1M. Production identity/config/credential provisioning, HTTP/sampling, session transactions, cancellation/rollback, residency and SSD tiers remain absent. These results must not be presented as physical three-PC/full-quant/GPU validation.

Owned-loader qualification uses a synthetic six-layer GLM fixture with small dimensions. It verifies exact rank tensor sets, byte-for-byte provider/file payload equality, owned byte counters, invalid plans/modes, refusal of ordinary context creation/export, and closure of file handles. The source GGUF is removed after use. The experimental side header compiles as C and exports unmangled model/context symbols in the shared library.

Local forward qualification executes three independent owned models/contexts in one process against an unchanged monolithic six-layer oracle. Two splits (2/2/2 and 1/1/4) include pure-KDA and pure-DSA stages. The fixture selects eight of sixteen experts, retains the shared expert, and uses sparse index top-k 8. It processes 131 tokens in chunks 1/3/4/17/31/64/11, crossing four-token pool tails and a two-ubatch chunk. Both captured oracle boundaries are byte-exact; the largest final-logit absolute error with terminal last-row pruning is 3.35276127e-8 (seed 53, GCC 14.2 CPU). Tests inspect every layer's FP32 recurrent and FP16 MLA/index allocation and require absence of unowned state. A/B output all residual rows even when no row requests logits. Negative cases cover wrong contexts/cache precision, duplicate positions, B token input, encoder/noncausal modes and disabled headless output. Injected CPU aborts invalidate the context permanently; clearing memory cannot re-admit it, while recreating the context retains the loaded weights. This is not three-process TCP or GPU execution.

The same stage fixture passes native MSVC CPU in CPU and CUDA-linked Windows builds at 2a5360405 and 0e720734d. Downloaded 0e720734d CPU evidence reports exact boundaries and maximum logit absolute error 4.47034836e-8. Its LastTest.log reports nine wire suites; PE inspection confirms test-glm-wire.exe imports bcrypt.dll, with no OpenSSL DLL. The earlier 1410c4041 CUDA artifacts have a real PE delay-import directory and no direct nvcuda.dll import, and their CPU launch/tests passed. These establish native compilation and hosted CPU behavior, not GPU execution or standalone dependency packaging.

No target-model logits, full-context allocations, GPU residency, timing or tokens/sec measurements exist. Windows Actions will compile native application targets and run CPU fixtures; hosted runners do not prove NVIDIA inference correctness.

The planner integration cases construct tiny metadata-only GGUF files describing large tensors without allocating those payloads. They cover valid signed/unsigned schedules, middle-stage missing projections, incorrect expert counts, truncated headers, invalid splits, excessive counts and context refusal. Temporary paths include spaces to exercise native argument quoting on Windows. The fixtures are structural, not quant-codec or inference tests.

Native schema validation uses a guarded descriptor-only loader mode: complete actual descriptors populate the ordinary native shape/count checks, rather than the synthetic provider path that creates expected tensors. The report checks every weight buffer is zero-sized and has no data. The six-layer fixture verifies the exact independent byte inventory and refuses nine cases: missing norm, wrong norm width, unknown tensor, invalid mHC stream count, missing KDA projection, missing DSA projection, invalid expert grouping, unknown rope scaling and unknown classifier activation. The planner also refuses an FFN-only structural fixture when native validation is requested. C header syntax and unmangled export checks pass locally. No payload bytes, GPU/cache allocations, residency or model integrity are established by this check.

Canonical identity has four local suites: system SHA256 empty/abc and multipart vectors, an independent 479-byte Python encoding/hash golden, 21 field-change digest checks and 22 malformed-contract refusals. Shard enumeration order is canonical; Windows case aliases, path names, duplicate/gapped indices and oversized facts refuse. The three-process fixture validates native descriptors and hashes only the bounded GGUF header. Changing one tokenizer string while keeping geometry and all weight payloads unchanged causes authenticated startup refusal with zero output on A/B/C. This also passes native Windows CNG/CPU at 1c1dade88. No payload checksum, binary attestation or resource/residency guarantee is implied.

The whole-chunk bridge has eight local TCP suites: bit-exact 128 MiB over 32 authenticated fragments; a 64 KiB plus 2 KiB tail at the final allowed context positions; no partial-input return; eight interleaved/repeated coordinate refusals; truncated final body; bad final MAC; zero/insufficient/excessive local input budgets; and an incomplete-chunk deadline. All use real loopback sockets. The bridge owns one bounded input float buffer and one incoming frame, and exposes values only after complete validation. The model fixture now sends its 64-row chunk in two 64 KiB fragments, with unchanged byte-exact boundaries/logits. All eight suites and the fragmented model fixture pass in CPU/SM89/SM120a Windows jobs at f11238d49; downloaded CPU evidence confirms these outputs. These are CPU transport/buffer fixtures, not a 128 MiB GPU allocation or 1M model run.

Storage has six local suites: exact multi-read/tail bytes with Unicode/space paths and move ownership; 200 concurrent reads through one file handle; a tiny physical sparse fixture with a marker above the 4 GiB offset; pre-I/O invalid-span/overflow/null/size refusal and permanent invalidation; source mutation protection (POSIX change detection, Windows write-sharing denial when qualified); and sealed exact-catalog leases with concurrent lookups, strict budgets, missing-expert refusal and retained backing bytes. No source file is mapped. These are primitives, not model-integrated expert caching or a host page-lock/GPU residency result. These six suites pass native Windows at 67608b0e9 in CPU/SM89/SM120a jobs, confirmed by downloaded CPU evidence.

Four further local storage suites qualify the new desktop cache: exact leased bytes under capacity refusal/eviction, a concurrent eight-reader miss producing one shared native read (seven waited in the observed run), permanent failure with zero retained reservations and no work admitted on a healthy second file, and 200 weak-lock/eviction stress iterations with payload/entry limits. Rank 1 and overlapping catalogs refuse. A GCC 14.2 ThreadSanitizer build of the complete native storage/cache test ran all ten suites with exit 0 and no report. Nine focused CTest targets plus four GLM tests pass. All ten storage/cache suites pass native MSVC at e0e467c26 in CPU/SM89/SM120a jobs; downloaded CPU evidence also reports seven actual waiters for one native load. File-call counters measure requested native I/O, not physical NVMe transactions; OS file caching remains outside these payload counters.

The expert-bank target runs five local suites. Four mixed-type cases cover all eight publisher tensor types with native GGML CPU MUL_MAT_ID operations, three projections, eight of sixteen selected experts over three token rows, and nonconstant original-ID scales. Full independent tensors provide references. Cold/hot/replacement phases are byte-exact, and native-read counters are 24/24/48. An intentionally wrong scale lookup by slot differs, proving the fixture detects that error. The fifth suite covers budget/ID/distinct-cap refusal before provider reads and permanent invalidation after two slabs were copied but a third source slab failed. Active same-thread and concurrent leases prevent overwrite; moved leases refuse use. All five suites pass native MSVC CPU in CPU/SM89/SM120a Windows builds at 8e1820a0d, confirmed by downloaded CPU evidence. These are projection operators, not a complete streamed-model or GPU execution result.
