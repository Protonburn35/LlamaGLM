# Transactional native CPU sampling

`sampling_transactions` owns a C-side native sampler chain and one pending clone. The configured policies are explicit greedy, or temperature followed by the inherited native full-vocabulary distribution sampler with an explicit seed. Unknown policies, random sentinel seeds, nonfinite/nonpositive temperatures and noncanonical greedy parameters refuse. This component does not change ordinary llama.cpp sampling or enable stochastic RPC/HTTP requests.

The configuration fingerprint is SHA256 of 32 canonical bytes: `GLMSAMP\0`, LE32 version 1, mode, vocabulary, seed, IEEE FP32 temperature bits and diagnostic candidate count. Vocabulary is bounded at 1,048,576 and diagnostics at eight; every parameter is bound. Wire mode 1 remains greedy-only, and a future stochastic wire/configuration agreement must bind this fingerprint before enabling mode 2. Header/model identity alone does not bind a generation request's sampling policy.

`draw` accepts the actual applied C receipt and canonical LE FP32 logits for every row. It checks exact dimensions, the 128 MiB payload bound, complete output digest, C ownership and session/transaction position using the existing owner ledger. It samples only the final row, rejects nonfinite or overflowing scaled scores, clones the committed native chain, then applies/accepts the selected token on the clone. Top-eight diagnostics retain original raw FP32 logits and do not restrict the full sampling distribution. A pending result has no certificate fingerprint and cannot be published.

`complete_after_global` validates the complete A/B/C certificate against the pending actual C receipt, promotes the pending native chain and advances the draw ordinal once. The caller must separately establish global completion; this API cannot prove that network event. Exact pending or last-committed draw/completion retries return the original selection without another RNG draw. A late old completion cannot replace a newer pending clone. All errors and explicit invalidation permanently discard both sampler owners and cached results; ordinary sampling may resume only with a new instance and coherent replay.

The real model-process fixture draws through this component before C sends its applied receipt. C promotes the clone only after decoding A's authenticated global completion against its local commit. The existing greedy terminal encoder additionally requires the canonical greedy configuration, so the new local distribution policy cannot enter the greedy-only wire accidentally. Lost B ACK paths invalidate the sampler with the context/replies. Fresh context epochs rebuild the sampler; synthetic greedy regeneration remains exact. Per-owner evidence requires one committed sampler draw per actual transaction on C and zero on A/B, including healthy network retry and retained-prefix recovery.

Six suites cover independent Python configuration bytes/hashes, canonical refusals, final-row/tie greedy selection, 64 seeded full-vocabulary draws against a separate native sampler, pending/committed/late retries, complete-certificate conflicts, hash/role/session/size errors, native RNG replay after a discarded pending draw, nonfinite/overflow values, one-token vocabulary and refusal before touching an oversized payload. More than half the distribution selections must lie outside the eight diagnostic candidates. The component/test code also passes standalone ASan/UBSan while linking the already qualified native core; that run does not instrument the entire core.

This is a single-writer CPU primitive. It does not serialize native RNG state, provide a durable client/sampler journal, implement grammar/penalties/top-k/top-p/min-p/Mirostat policies, configure GPU sampling, prove laptop residency or grant production admission. Those modes must be added with complete identity/clone/retry/replay checks. Stochastic RPC, user API and real model/GPU/physical-PC/1M execution remain unimplemented or NOT_RUN.
